# Finance Tracker

**Русский** | [English](README.en.md)

[![ci](https://github.com/AsyncAssassin/finance-tracker-clean/actions/workflows/ci.yml/badge.svg)](https://github.com/AsyncAssassin/finance-tracker-clean/actions/workflows/ci.yml)

Приложение на Go для учёта личных расходов и бюджетов. Пользователь работает
в Google Таблице: задаёт лимиты, вносит расходы и получает отчёт по категориям.
HTTP API также поддерживает импорт и экспорт CSV.

**Стек:** Go, gRPC, PostgreSQL, Redis, Google Apps Script, Docker Compose, Caddy.

## Попробовать приложение

Для проверки готового стенда получите у автора ссылку на шаблон Google Таблицы,
адрес API и данные входа. Создайте личную копию таблицы и выполните
[сценарий на 10 минут](docs/demo.md): бюджеты, расходы, отказ по лимиту и отчёт.
Устанавливать Go или Docker не требуется. Доступ предоставляется индивидуально;
для самостоятельного запуска используйте [быстрый старт](#быстрый-старт).

## Возможности

- Расходы с датой, категорией, суммой и описанием.
- Бюджеты на месяц, год или всё время; превышение лимита отклоняется.
- Отчёт за период: расходы, остатки и процент использования бюджета.
- Импорт CSV с результатом каждой строки и экспорт для дальнейшего анализа.
- Отдельные данные пользователей, регистрация и вход по JWT.
- Работа через формы и меню Google Таблицы, повторная отправка без дублей.

## Инженерные решения

**Проверка бюджета при параллельных расходах.** Деньги хранятся в целых копейках.
Проверка лимита и запись расхода выполняются в одной транзакции PostgreSQL
с блокировкой категории, в том числе когда бюджет ещё не создан.
[Реализация и ограничения](docs/architecture.md#деньги-и-бюджеты).

**Управляемый параллелизм импорта.** Строки одной категории или с одинаковым
`external_id` обрабатываются по порядку. Независимые группы выполняются
параллельно с общим лимитом работников. Повторы не создают дубли, отмена
останавливает оставшуюся работу и сохраняет уже записанные строки.
[Устройство импорта](docs/architecture.md#параллельный-импорт).

**Кеш с защитой от устаревшей записи.** Версия данных пользователя входит
в ключ отчёта. Изменение бюджета или расходов делает прежние отчёты
недействительными; при сбое Redis отчёт строится по PostgreSQL.
Механизм рассчитан на один экземпляр Ledger.
[Устройство кеша](docs/architecture.md#кеш-отчётов).

## Архитектура

```text
Google Таблица / HTTP-клиент
              |
         HTTPS (Caddy)
              |
           Gateway
          /       \
       gRPC       gRPC
        /           \
      Auth         Ledger ----- Redis
        \           /
          PostgreSQL
```

Gateway принимает HTTP, проверяет JWT и вызывает сервисы по gRPC.
Auth управляет аккаунтами и токенами. Ledger отвечает за расходы, бюджеты,
отчёты и CSV. У Auth и Ledger отдельные схемы, роли БД и миграции Goose.
Миграции выполняют отдельные процессы с правами владельцев своих схем.

Домен и сценарии использования отделены от HTTP, gRPC и хранилищ интерфейсами.
Подробности: [слои, контракты и хранение](docs/architecture.md).

## Быстрый старт

Нужен Docker с Compose 2.24.4 или новее. Команды ниже предназначены для новой
локальной установки. При обновлении существующего стека сохраните его `.env`
и тома, следуйте [инструкции обновления](docs/operations.md#обновление-и-откат).

```sh
git clone https://github.com/AsyncAssassin/finance-tracker-clean.git
cd finance-tracker-clean
install -m 600 .env.example .env
printf '\nJWT_SECRET=%s\n' "$(openssl rand -base64 32)" >> .env
for name in REDIS_PASSWORD POSTGRES_PASSWORD AUTH_DB_PASSWORD LEDGER_DB_PASSWORD AUTH_MIGRATION_PASSWORD LEDGER_MIGRATION_PASSWORD; do
  printf '%s=%s\n' "$name" "$(openssl rand -hex 32)" >> .env
done
# Для локального примера; на сервере укажите адреса участников пилота.
printf 'AUTH_REGISTRATION_EMAILS=anna@example.com\n' >> .env
docker compose up --build -d --wait
curl -fsS http://localhost:8080/ping
```

Регистрация закрыта по умолчанию. Список email разрешает создание аккаунтов,
но не проверяет владельца почты. Порядок допуска участников описан
в [эксплуатации](docs/operations.md#закрытый-пилот-и-квоты).

Ожидаемый ответ: `pong`. Без `JWT_SECRET` Auth и Gateway не запускаются.
Compose сначала завершает `auth-migrate` и `ledger-migrate`, затем запускает сервисы. PostgreSQL хранит данные в томе `pgdata`;
`docker compose down` сохраняет его, `docker compose down -v` удаляет.

В обычном Compose опубликован только Gateway на `127.0.0.1:8080`.
PostgreSQL, Redis и gRPC доступны внутри сети контейнеров.
`/ping` проверяет сам Gateway; вход и запрос бюджета проверяют также Auth и Ledger.

**API:** [Swagger UI локально](http://localhost:8080/docs),
[OpenAPI в репозитории](api/openapi.yaml).
Для запуска Go-сервисов без контейнеров нужен Go 1.26.9 или новее:
[режим разработки](docs/operations.md#локальная-разработка).

## Пример API

Команды выполняются последовательно в одном терминале. Создаётся отдельный
демонстрационный аккаунт с разрешённым email и случайным паролем.
Пример использует новую базу; для уже созданного аккаунта нужен вход. Требуются `curl` и `openssl`.
Для собственного публичного стенда замените `BASE_URL` на его HTTPS-адрес.

```sh
BASE_URL=http://localhost:8080
DEMO_EMAIL=anna@example.com
DEMO_PASSWORD=$(openssl rand -hex 16)
LOGIN_JSON=$(printf '{"email":"%s","password":"%s"}' "$DEMO_EMAIL" "$DEMO_PASSWORD")
AUTH_JSON=$(printf '%s' "$LOGIN_JSON" | curl -fsS "$BASE_URL/api/auth/register" \
  -H 'Content-Type: application/json' --data-binary @-)
TOKEN=$(printf '%s' "$AUTH_JSON" | sed -nE 's/.*"access_token":"([^"]+)".*/\1/p')
test -n "$TOKEN"

curl -fsS -X POST "$BASE_URL/api/budget" \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"category":"еда","limit":5000,"period":"month"}'
curl -fsS -X POST "$BASE_URL/api/transactions" \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"amount":"1250,50","category":"еда","description":"продукты","date":"2026-10-05","external_id":"example-1"}'
curl -fsS -H "Authorization: Bearer $TOKEN" \
  "$BASE_URL/api/reports/summary?from=2026-10-01&to=2026-10-31"
```

Регистрация, создание бюджета и расхода возвращают `201`. Итог отчёта нового
аккаунта: 1250,50; остаток бюджета: 3749,50. Повтор расхода с тем же
`external_id` даёт `409 already_exists`. Ещё 4000 в той же категории и месяце
дадут `409 budget_exceeded`; без токена защищённые маршруты отвечают `401`.

Периоды бюджета: `month`, `year`, `none`; по умолчанию `month`.
`/api/budgets` является алиасом `/api/budget`.
Повторный `POST /api/budget` обновляет бюджет и возвращает `200`.
[Полный сценарий, маршруты, ошибки и CSV](docs/api.md).

## Google Таблицы

Интерфейс реализован в [sheets/](sheets): `Code.gs`, `Login.html`,
`AddTransaction.html`, `appsscript.json`. Для подключения нужен собственный
[HTTPS API](docs/operations.md#публичный-https), доступный из Google.

1. Создайте Google Таблицу и откройте **Расширения → Apps Script**.
2. Включите показ манифеста в настройках редактора. Перенесите четыре файла
   из `sheets/`; HTML-файлы создайте как `Login` и `AddTransaction`.
3. Сохраните проект, обновите таблицу и выполните
   **Finance Tracker → Подготовить листы**.
4. Через **Подключение…** разрешите работу с текущей таблицей, показ форм
   и внешние запросы. Укажите свой адрес вида `https://api.example.com`.
   Нужен HTTPS на порту 443 без пути; `localhost` из Google недоступен.
5. Выберите **Войти или зарегистрироваться…**, проверьте адрес сервера
   и войдите в заранее подготовленный аккаунт Finance Tracker.
   Регистрация доступна только адресам из списка администратора.
6. Заполните лист **Бюджеты** и сохраните его через меню. Добавьте расход
   через форму либо заполните строки и выберите **Отправить новые строки**.
7. На листе **Отчёт** задайте даты в B1:B2 и загрузите отчёт через меню.
   Данные появятся с A4; D2 показывает HIT/MISS кеша.

Ввод в ячейки отправляется командой меню. ID и ключи сохранённых расходов
защищают от дублей при повторе. [Сценарий с ожидаемыми суммами](docs/demo.md),
[копирование готовой таблицы и решение ошибок доступа](docs/sheets.md).

## Тесты

```sh
make test              # Go-тесты; внешние интеграции включаются отдельно
make race              # Go-тесты с детектором гонок
make test-integration  # отдельная база PostgreSQL и Redis 15
make sheets-test       # Apps Script в Node 22+, без интерфейса Google
make cover-all         # полный профиль с PostgreSQL, Redis и -race
```

HTTP e2e запускается на отдельном тестовом стеке:
[команды и границы проверок](docs/testing.md).
Профиль [cover.out](cover.out) сохранён для сдачи проекта. Его область измерения
и получение нового профиля описаны в [тестировании](docs/testing.md#покрытие-и-ci).
Результаты запусков и артефакты доступны в
[GitHub Actions](https://github.com/AsyncAssassin/finance-tracker-clean/actions/workflows/ci.yml).
CI проверяет Go-код, интеграции, HTTP-сценарии, скрипт таблицы, HTTPS-конфигурацию,
зависимости и секреты. Node-тесты не заменяют запуск в интерфейсе Google.

## Ограничения развёртывания

Конфигурация рассчитана на закрытый пилот с одним Auth и одним Ledger.
До 100 аккаунтов на установку, 10 000 транзакций и 100 категорий на аккаунт. Счётчики входа хранятся
в памяти Auth; согласование кеша между несколькими Ledger не реализовано.
Нет восстановления пароля и индивидуального отзыва JWT: выход очищает
сессию клиента, а выданный токен действует до истечения срока.
CSV-экспорт ограничен 100 000 строками и собирается в памяти.
[Модель доступа](docs/architecture.md#модель-доступа) и
[ограничения развёртывания](docs/architecture.md#ограничения-развёртывания).
