# Google Таблица

[README](../README.md#google-таблицы) · [Демонстрация](demo.md) · [Исходники Apps Script](../sheets)

Google Таблица служит интерфейсом к API. Разрешения Google дают скрипту доступ
к таблице, а вход в Finance Tracker определяет владельца данных на сервере.
Это разные аккаунты и разные разрешения.
Используйте API и скрипт из одного выпуска; порядок обновления описан
в [эксплуатации](operations.md#обновление-и-откат).

Для самостоятельной установки начните с [новой таблицы](#новая-таблица-с-нуля).
Копирование удобно, если другой пользователь уже подготовил шаблон.

## Подключение копии

1. Получите у владельца ссылку на настроенную таблицу и откройте её
   с аккаунтом, которому предоставлен доступ. Через **Файл → Создать копию**
   сохраните личную копию на Диск. **Скопировать настройки доступа** не отмечайте.
   Возможность копирования должна быть разрешена владельцем исходной таблицы.
2. В копию переносятся листы и привязанный Apps Script. Обновите страницу,
   если меню **Finance Tracker** ещё не появилось. Работайте с правами редактора
   своей копии; просмотр исходной таблицы сам по себе не запускает сценарий.
3. Выберите **Finance Tracker → Подключение…**. Google запросит три права:
   текущая таблица, подключение к внешнему сервису и показ форм.
   Они заданы в [манифесте](../sheets/appsscript.json).
   При предупреждении о непроверенном приложении сверьте проект и исходники
   своей копии. Для него переход расположен в **Дополнительных настройках**;
   выдавайте только перечисленные права. Если окно подключения не появилось
   после авторизации, снова выберите команду меню.
4. Укажите публичный HTTPS-адрес API без `/api` и `/docs`, например
   `https://api.example.com`. Разрешён порт 443, без логина, пути и параметров.
   `localhost` из Apps Script недоступен. Дождитесь **Подключено: …**.
5. Откройте **Войти или зарегистрироваться…**, проверьте адрес сервера в форме.
   Создайте отдельный аккаунт Finance Tracker с паролем от 15 символов,
   либо войдите в существующий. Пароль Google здесь не вводится.
6. После копирования заново задайте адрес API и войдите в свой аккаунт.
   Скопированные ID, статусы и отчёт относятся к прежнему примеру,
   а не к новому аккаунту API.
7. Для первого сценария нового аккаунта очистите только примеры в копии:
   `Транзакции!A2:G1000` и `Бюджеты!A2:D1000`. Введите диапазон в поле имени
   слева от строки формул и удалите содержимое. Сохраните первую строку
   с заголовками и сами листы. Данные API этим не удаляются.
8. На листе **Отчёт** задайте период в B1:B2 и загрузите отчёт через меню.
   У нового аккаунта итог должен быть 0. Затем выполните [демонстрацию](demo.md).

## Новая таблица с нуля

Перенос скрипта, настройка подключения и первый вход описаны в
[README](../README.md#google-таблицы). Ниже приведены команды меню,
правила повторной отправки и способы устранения ошибок.

## Меню и листы

| Команда | Действие | API |
| --- | --- | --- |
| Подключение… | Сохраняет адрес для документа и проверяет `/ping` | `GET /ping` |
| Войти или зарегистрироваться… | Получает JWT в личную сессию пользователя скрипта | `POST /api/auth/login`, `/register` |
| Добавить транзакцию… | Открывает форму и добавляет строку с ID | `POST /api/transactions` |
| Отправить новые строки листа «Транзакции» | Отправляет строки без ID; записывает результат каждой строки | `POST /api/transactions/import` |
| Загрузить отчёт за период | Читает B1:B2, пишет отчёт с A4 и HIT/MISS в D2 | `GET /api/reports/summary` |
| Сохранить / загрузить бюджеты | Передаёт категорию, лимит и период | `POST/GET /api/budget` |
| Выйти | Очищает личную сессию скрипта | Нет |
| Подготовить листы | Создаёт недостающие листы и заголовки | Нет |

Лист **Транзакции**: A дата, B категория, C сумма, D описание, E ID,
F статус, G ключ. Колонка ключа соответствует `external_id`.
Лист **Бюджеты**: A категория, B лимит, C период, D результат сохранения.
Числа в ячейках бюджета начинают действовать после команды сохранения.

Сам ввод ячеек не отправляет запросы. Отправка выполняется через меню;
строки с ID пропускаются, строки без ID проверяются снова. **Подготовить листы**
не очищает существующие данные. При смене API-аккаунта ячейки тоже не очищаются.

Регистрация ограничена списком email администратора. Подготовьте участников
по [порядку пилота](operations.md#закрытый-пилот-и-квоты). Пустой список закрывает
регистрацию, но существующие аккаунты продолжают входить.

## Сессии и повторная отправка

Токен хранится в `UserProperties`, адрес API в `DocumentProperties`.
Сессия привязана к выбранному адресу. Смена сервера требует нового входа.
При истечении JWT выберите **Войти**, повторная регистрация не нужна.
**Выйти** удаляет сессию скрипта, но не отзывает JWT на сервере.

Скрипт создаёт ключ транзакции до отправки. После первой отправки формы
поля фиксируются: при ошибке связи повторите запрос в том же окне.
Для исправления данных после явного отказа API откройте новую форму.
Повтор с прежним ключом возвращает ID ранее сохранённого расхода.
Не удаляйте ID и ключи собственных сохранённых операций ради повторной отправки.
Для полного повторения демонстрации согласуйте новый API-аккаунт с администратором и очистите
только пример в своей копии.

Формы получают ожидаемый отказ API как обычный результат и показывают его
пользователю. Финансовые детали такого отказа не выбрасываются из серверной функции
как необработанное исключение; неожиданные ошибки получают фиксированный текст.
Обновляйте `Code.gs`, `Login.html` и `AddTransaction.html` вместе.

Редакторы таблицы могут менять привязанный скрипт, поэтому предоставляйте
редактирование только доверенным людям. Пароли и JWT не включаются в снимки,
экспорт примеров и переписку.

## Ошибки доступа

| Симптом | Действие |
| --- | --- |
| Нет меню Finance Tracker | Сохранить Apps Script, обновить страницу, проверить права редактора |
| Пустая форма, редактор не открывается, `PERMISSION_DENIED` | Открыть таблицу в сессии с одним Google-аккаунтом, например в приватном окне |
| 401 после смены адреса или истечения токена | Проверить адрес получателя и войти в Finance Tracker заново |
| 403 при регистрации | Использовать подготовленный аккаунт или согласовать допуск с администратором |
| 409 quota_exceeded | Достигнута квота пилота; читать и экспортировать данные можно, увеличение квоты согласовать с администратором |
| 503 server_busy | Подождать и повторить операцию с прежним ключом |
| 429 при входе или регистрации | Дождаться срока из `Retry-After`; новые попытки в том же окне не помогут |
| Копия содержит прежний отчёт | Загрузить отчёт своего аккаунта за выбранный период |
| Расход сверх бюджета без ID | Исправить данные или бюджет; сохранённые расходы не дублировать |

Apps Script не поддерживает одновременную работу с несколькими Google-аккаунтами
в одной сессии: [рекомендация Google](https://developers.google.com/apps-script/guides/support/troubleshooting#issues-multiple).
Доступ другого Google-пользователя проверяется по
[отдельному сценарию](demo.md#проверка-другим-пользователем).
