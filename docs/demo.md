# Демонстрация Finance Tracker

[Подключение Google Таблицы](sheets.md) · [Полный пример API](api.md#примеры)

Сценарий занимает примерно 7-10 минут: задать бюджеты, внести расходы,
увидеть отказ по лимиту и получить отчёт. Используйте личную копию таблицы
и новый демонстрационный аккаунт Finance Tracker. Пароли и JWT в снимки не включаются.

## Данные примера

Период отчёта: 2026-10-01 - 2026-10-31. Дата расходов: 2026-10-05.
Фиксированные даты позволяют повторять пример независимо от дня запуска.

| Категория | Бюджет | Период |
| --- | ---: | --- |
| еда | 5000 | month |
| транспорт | 2500 | month |

| Категория | Расход | Описание | Ожидаемый результат |
| --- | ---: | --- | --- |
| еда | 1250,50 | продукты | Сохранён |
| транспорт | 300,00 | проезд | Сохранён |
| здоровье | 700,00 | аптека | Сохранён, бюджета категории нет |
| еда | 4000,00 | превышение лимита | Отклонён: 1250,50 + 4000 больше 5000 |

Итог: **2250,50**. Остатки: еда 3749,50, транспорт 2200,00.
Использование бюджетов: еда 25,01%, транспорт 12%.

## Порядок показа

1. Проверьте `/ping` и `/docs` нужного API. `/ping` возвращает `pong`,
   `/api/budget` без токена отвечает 401. Используйте адрес своего
   стенда, например `https://api.example.com`.
2. Подключите собственную копию по [инструкции](sheets.md#подключение-копии).
   Очистите только скопированные примеры вместе с ID, статусами и ключами.
   Войдите в новый аккаунт API, загрузите отчёт за октябрь 2026: итог 0.
3. На листе **Бюджеты** заполните A2:C3 по таблице выше. Выполните
   **Сохранить бюджеты с листа «Бюджеты»**; обе строки должны получить статус **создан**.
4. Через **Добавить транзакцию…** сохраните расход на еду 1250,50 за 2026-10-05.
   На листе появятся ID и статус **сохранена**.
5. В A3:D5 листа **Транзакции** внесите остальные три расхода: дата, категория,
   сумма, описание. Колонки E:G оставьте пустыми. Выполните
   **Отправить новые строки листа «Транзакции»**.
6. У транспорта и здоровья должны появиться ID. У расхода 4000 ID остаётся пустым,
   статус объясняет превышение бюджета. Повторите команду: сохранено 0,
   одна ошибка, сохранённые расходы не дублируются.
7. На листе **Отчёт** задайте B1 `2026-10-01`, B2 `2026-10-31` и загрузите отчёт.
   Проверьте итог и остатки выше. После изменений первый запрос при работающем
   Redis даёт MISS; немедленный повтор даёт HIT.
8. Для демонстрации CSV и gRPC используйте [пример API](api.md#примеры)
   на отдельном аккаунте и [прямые вызовы gRPC](operations.md#прямой-доступ-к-grpc)
   в локальном режиме разработки. Повторный импорт экспорта не создаёт дубли.
9. Покажите состав сервисов, успешный CI и [cover.out](../cover.out).
   Дата, среда и границы проверок приведены в [результатах](security.md#результаты-проверок).
   Перезапуск и восстановление выполняются по [инструкции эксплуатации](operations.md#обновление-и-откат).

## Проверка другим пользователем

Получатель открывает исходную таблицу своим Google-аккаунтом, создаёт личную
копию, разрешает Apps Script и входит в свой заранее созданный аккаунт Finance Tracker.
Допуск участника готовится по [порядку пилота](operations.md#закрытый-пилот-и-квоты).
Затем повторяет шаги 2-7. Проверка под другим API-аккаунтом внутри Google-сессии
владельца не заменяет этот сценарий.

Доступ к приватному репозиторию предоставляется отдельно от доступа Google.
Перед демонстрацией нужно убедиться, что получатель открывает обе ссылки.
Статус этой проверки ведётся в [оставшихся действиях](security.md#текущее-состояние-и-оставшиеся-действия).
