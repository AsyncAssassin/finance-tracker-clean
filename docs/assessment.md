# Проверка требований итогового проекта

Finance Tracker подготовлен как индивидуальный итоговый проект курса «Язык Go».
Таблица ниже сопоставляет десять критериев задания с реализацией и способом
проверки. Результаты выполненных прогонов и оставшиеся действия находятся
в [отчёте безопасности](security.md#текущее-состояние-и-оставшиеся-действия).

## Соответствие критериям

| № | Критерий | Реализация и порядок проверки |
| --- | --- | --- |
| 1 | Репозиторий и запуск | [README](../README.md#быстрый-старт), [.env.example](../.env.example), [Compose](../compose.yaml): запустить стек, получить `pong` от `/ping`. В README есть [OpenAPI](../api/openapi.yaml) и пример curl |
| 2 | Базовое API | [Сценарий API](api.md#примеры): POST/GET `/api/budget` и `/api/transactions`. Успешное создание даёт 201, неверные поля 400; единый JSON ошибок и 500 покрыты [HTTP-тестами](../internal/gateway/rest/rest_test.go) |
| 3 | PostgreSQL и миграции | [Goose-миграции](../migrations), [репозитории](../internal/ledger/repo/postgres): повторный POST бюджета обновляет его и возвращает 200. [Контрактные тесты](../internal/ledger/repo/repotest) и проверка перезапуска подтверждают сохранение данных |
| 4 | Бюджет, отчёт и CSV-экспорт | [Правила бюджета](api.md#как-работает-бюджет), [пример](api.md#примеры): превышение даёт 409 без вставки; summary принимает from/to; export.csv возвращает сохранённые расходы |
| 5 | Тестирование | Табличные тесты [домена](../internal/ledger/domain) и [HTTP](../internal/gateway/rest), команды [make test / race / cover-all](testing.md#команды), сохранённый [cover.out](../cover.out). Свежесть и результат CI указаны в отчёте безопасности |
| 6 | Redis | [Кеш](../internal/ledger/cache/redis), REPORT_CACHE_TTL, [проверка MISS → HIT → MISS](api.md#проверка-кеша). Повторный отчёт использует кеш, запись инвалидирует его |
| 7 | gRPC | Ledger и Auth работают отдельными процессами в Compose; Gateway вызывает их по [proto-контрактам](../api/proto). [Таблица преобразования статусов](architecture.md#grpc-и-обработка-ошибок), [прямые вызовы](operations.md#прямой-доступ-к-grpc) |
| 8 | JWT | Регистрация/вход выдают токен, финансовые маршруты без него дают 401. [Модель доступа](security.md#модель-доступа), секреты из окружения, [защищённый запрос в README](../README.md#пример-api) |
| 9 | Google Таблицы | [Скрипты и формы](../sheets), [подключение в README](../README.md#google-таблицы), [демонстрация](demo.md): создать расход и получить отчёт в лист. Другой Google-пользователь проверяет доступ и свою копию отдельно |
| 10 | CSV-импорт или bulk | Реализован [CSV-импорт](api.md#csv-импорт) с валидацией и результатом каждой строки. Дополнительно есть [параллельная обработка](architecture.md#параллельный-импорт), отмена контекста и тесты с -race; отдельный /bulk для выбранного варианта критерия не требуется |

Основные функциональные требования также покрыты этими сценариями: хранение
расходов с суммой, категорией, описанием и датой; бюджеты; импорт/экспорт;
отчёт с итогом и процентом использования; Google-интерфейс; JWT.
[Архитектура](architecture.md#сервисы-и-слои) показывает Go-сервисы, gRPC,
HTTP Gateway, PostgreSQL/Redis и разделение домена, сценариев и адаптеров.

Адрес `POST/GET /api/budgets` из критерия 2 является алиасом `/api/budget`.
Оба используют те же обработчики, авторизацию и данные; Google Таблица
продолжает работать с прежним адресом.

## Порядок проверки

1. Получить доступ к репозиторию и исходной Google Таблице. Копирование таблицы
   должно быть разрешено; проверяющий запускает скрипт в своей копии.
2. Выполнить быстрый старт README, открыть Swagger UI и повторить защищённый запрос.
3. Выполнить [полный сценарий API](api.md#примеры), включая бюджеты, расходы,
   отказ по лимиту, отчёт, CSV и кеш. Сверить состав сервисов через Compose.
4. Запустить проверки на отдельном стенде по [инструкции тестирования](testing.md).
   Проверить CI, профиль покрытия и датированные результаты.
5. Выполнить [демонстрацию Google Таблицы](demo.md) со своим API-аккаунтом.

Сам ввод ячейки не отправляет запрос: пользователь запускает команду меню,
после чего Apps Script обращается к API и записывает результат. Это обеспечивает
две операции критерия 9. Если общая формулировка задания об автоматическом вызове
понимается как отправка при каждом редактировании ячейки, такое поведение
требует отдельного уточнения: обработчика onEdit в проекте нет.

ссылка на настроенную Google Таблицу и [сценарий демонстрации](demo.md).

может обозначить проверенную версию, но отдельного требования тега в задании нет.
Реализация и доказательства проверок не предопределяют оценку преподавателя.
